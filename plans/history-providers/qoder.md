# Qoder global CLI history acquisition

Tracked by #457. This adapter targets the global `@qoder-ai/qodercli` npm release 1.1.75 on macOS arm64. It does not claim Qoder CN, IDE, SDK or older CLI formats.

The published package tarball SHA-256 is `735c86ef516d92505b415029609cb015ce95d6e442b63fb9a59d7078636c9227`; its `bundle/qodercli.js` SHA-256 is `1b5b17bb25bcd2e059a97e8bc1d4280e4c16fb4194b004463cd677c434536948`. The bundle's `Ap` function resolves `<config>/projects/<project-hash>/<session-id>.jsonl`. The released `TranscriptStore` writes the lines; the separate released `Repository.resolveSession(..., {view: 'historical'})` reads them after the writer closes. `QODER_CONFIG_DIR` changes the global config root; RelayHistory freezes that value when opening the store, anchoring a relative value to the opening process directory, with `<home>/.qoder/projects` as default. Its explicit `ProviderRoots` override wins over environment resolution.

The fixture capture invokes those shipped writer and reader classes with synthetic inputs. Because the npm executable exposes no library exports, [capture.mjs](fixtures/qoder/capture.mjs) checks the exact bundle hash and changes only the CLI launch statement in a temporary extracted copy to expose the classes. It does not run the CLI's authentication or a model turn. The writer output and independent restart reader are committed at [fixtures](fixtures/qoder/README.md). The run proves the writer preserves user/assistant UUID and parentUUID, model, tool-use and tool-result IDs, cwd, timestamps and resume append. The successful transport case uses distinct timestamps written by the native writer. A separate native same-millisecond case proves that remote event ordering can conflict with local replay: hydration must fail with `FILE_HISTORY_SHARED_ORDER_CONFLICT` and keep the earlier remote snapshot. General remote ordering recovery is tracked in #463. An ad hoc assistant `usage` object was supplied in a separate probe and was stripped by the writer; no usage is inferred. Native `/resume` command behavior remains unverified.

Discovery lists only immediate project directories and their JSONL children, skipping directory symlinks. It reads a 64 KiB head, continuing only through a complete opening record up to an 8 MiB cap; a larger opening record produces a per-candidate diagnostic while healthy siblings remain available. The same open file handle supplies a bounded tail so recent native timestamps advance shallow activity after long runs and resumed appends. Hydration snapshots the selected file, validates its native session ID and normalizes complete user/assistant records; tool results do not become user prompts. Complete rewrites retire removed evidence. An incomplete tail is deferred while prior evidence remains. Control records remain markers, including the CLI's integer-millisecond control timestamps. The adapter never starts Qoder or uses network, authentication or models while scanning.

Verification must include public Rust discover/hydrate/read/reopen/change/export, CLI search, SDK and MCP filtering, root/path/collision handling, and removal negative control. Keep #457 open if any required public transport proof remains incomplete.
