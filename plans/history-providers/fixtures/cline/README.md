Obtain those three exact files from the pinned Git commit and run `node capture.mjs <download-dir>`. The capture requires Bun, but no Cline sign-in, models, network requests, or private session data. It supplies only import stubs, deterministic `nowIso`, a row lookup containing the synthetic path, and a `nanoid` stub that fails if a fixture ID is absent. The extracted method bodies remain byte-for-byte upstream source. The ordinary case writes one prompt and answer. The resumed case writes a first snapshot, then overwrites it with a second turn under the same native session ID and stable first-turn IDs. This is snapshot continuation evidence, not a claim that the `cline resume` CLI command was exercised. The reader runs in a fresh process and its exact projected output is `restart-reader.json`; it confirms IDs, roles, content, model metadata, assistant timestamps and metrics after restart. The original golden stays separate from the generated artifacts.

Core's `resolveSessionDataDir` in `sdk/packages/shared/src/storage/paths.ts` selects `CLINE_SESSION_DATA_DIR`, then `CLINE_DATA_DIR/sessions`, then `CLINE_DIR/data/sessions`, then `HOME/.cline/data/sessions`. Programmatic `setClineDir` can override the environment inside a running Cline process and is not observable by passive discovery. RelayHistory's explicit `ProviderRoots` wins for its own store. The source writer calls `writeFileSync` on the populated snapshot without an atomic replacement, so a concurrent read can see partial JSON; the adapter rejects that snapshot and retains the previous complete evidence. The source reader explicitly treats malformed/empty artifacts as no messages. Cline CLI `history export` calls `readSessionMessagesArtifact` through `core.readMessages` and can export JSON or HTML after restart; this capture executes the lower level independent reader that the history path uses. The native `messages.json` contract says its artifact alone is canonical for replay/export, while `hooks.jsonl` is optional telemetry.

Terminal assistant `metrics` can represent per-turn counters or a fallback copied from the total run usage, according to `withLatestAssistantTurnMetadata`. This capture does not prove which each record represents, so the provider stores a bounded raw marker and leaves normalized usage unavailable. User messages have no native `ts`; RelayHistory marks whether it derived their time from the next assistant `ts` or `updated_at`. No relationship, edit or native resume capability is claimed from the file-level agent label.
