# Goose historical acquisition (#450)

Pinned upstream: `aaif-goose/goose` commit `5be3f8d3db9a2c4dfd5162bc50c3a35c648b7706` (2026-10-22), current SQLite schema version 17. The native writer and independent reader are in [`session_manager.rs`](https://github.com/aaif-goose/goose/blob/5be3f8d3db9a2c4dfd5162bc50c3a35c648b7706/crates/goose/src/session/session_manager.rs); the process path resolver is [`paths.rs`](https://github.com/aaif-goose/goose/blob/5be3f8d3db9a2c4dfd5162bc50c3a35c648b7706/crates/goose/src/config/paths.rs); the persisted message contract is [`message.rs`](https://github.com/aaif-goose/goose/blob/5be3f8d3db9a2c4dfd5162bc50c3a35c648b7706/crates/goose-provider-types/src/conversation/message.rs).

`SessionStorage::new(Paths::data_dir())` opens `data_dir/sessions/sessions.db` in WAL mode. An absolute `GOOSE_PATH_ROOT` makes `data_dir` equal to `<root>/data`; a relative override is ignored. Without the override, Goose calls etcetera 0.11's `choose_app_strategy`: XDG on macOS and Linux (`${XDG_DATA_HOME:-~/.local/share}/goose`), and the Windows app strategy (`Block/goose/data` beneath its data directory). The Goose source comment mentions an older `~/Library/Application Support/Block/goose` convention, but the pinned dependency's executable resolver currently selects XDG on macOS. The session manager creates `schema_version`, `sessions`, `messages`, and `usage_ledger`; version 17 messages have `id`, `message_id`, `session_id`, `role`, `content_json`, `created_timestamp`, `timestamp`, `tokens`, and `metadata_json`. It reads a conversation ordered by `(created_timestamp, id)`, restores provider `message_id`, and exposes `get_session(id, true)` and `export_session(id)` independently of the writer.

The writer appends user/assistant messages and may replace the entire conversation. Each content block has a tagged `type`: `text`, `toolRequest`, `toolResponse`, `thinking`, and other provider types. Tool requests and responses share their native block `id`. Session-level and accumulated token counters are not per-message billable usage. `parent_session_id` is metadata until an independently proven child read shows a delegation contract. No native resume, live execution, file edit, or relationship capability is implied by the SQLite history source.

The native capture harness in `crates/ai-hist/tests/fixtures/goose/capture.rs` calls the pinned `SessionManager` writer from an isolated process, then starts a separate process for `get_session(id, true)` and `export_session(id)`. It repeats that reader after a third process appends a turn. The checked-in SQL dumps and official export JSON preserve the synthetic ordinary/tool/resumed messages, stable native IDs, and SQLite schema; only the temporary workspace path is sanitized. A later writer process replaces the conversation in the same database to test identity and retirement across native rewrites.

Local Goose hydration preserves native same-millisecond message order, including a `replace_conversation` reorder with stable native IDs. Shared source intake currently treats exported records as an identity set and can canonicalize a remote-only session into a different order within one millisecond. If that remote evidence then conflicts with a native local order, hydration reports `FILE_HISTORY_SHARED_ORDER_CONFLICT` and retains the prior remote snapshot. Durable ordering and ownership reconciliation for remote rewrites are tracked in [#532](https://github.com/AgentWorkforce/relayhistory/issues/532); remote-first order parity is outside this native acquisition claim.

The committed native fixtures exercise public discovery, hydration, search, session reads after reopen, export, remote intake, and rewrite/deletion rollback. The isolated SDK/CLI/MCP smoke uses the synthetic SQLite fixture; it invokes no Goose model or account. These local gates establish schema-17 historical acquisition, subject to review and CI, and do not imply broader Goose-version coverage or the shared remote-order guarantee in #532.
