# Mistral Vibe historical acquisition (#454)

Pinned source: `mistralai/mistral-vibe` commit `dd2c04ce717c417731ab89c333cd0a72541e33ba`, release 3.0.1. Its native writer and reader are `UnifiedSessionStore.write_generation`, `advance_projection_delta`, and `load` in `harness/runtimes/python/python/mistralai_vibe_local_harness/vibe/_storage.py`. The previous `SessionLogger` `messages.jsonl`/`meta.json` format is a legacy 2.x import source and does not represent current native sessions.

The current store lives at `<session_logging.save_dir>/unified/<sessionId>/`. `CURRENT` selects a generation; its digest pins `manifest.json`, whose descriptors pin checkpoint, runtime, and public projection documents. Long transcript runs are pooled into digest-named `chunks/` files. The active `journal/<sequence>.jsonl` has contiguous sequence numbers and record hashes; projection deltas can append, replace, or remove public entries. The importer validates these native structures before normalizing a complete capture. An incomplete final journal line, digest mismatch, unsupported delta, or concurrent pointer/journal change defers replacement of previously accepted evidence.

The synthetic fixture is written by the pinned 3.0.1 binary wheel via the official writer. Separate Python processes append a native projection delta and then run the official reader and interoperability export. It contains two user and assistant turns plus one completed tool effect. `fixtures/mistral-vibe/official-reader.json` records the independent reader's identity, cwd, title, entries, and export roles. A separate writer/reader pair proves two `ReplaceEntryOp` journal records update an existing assistant message and running tool effect under their original IDs; `pre-replace-reader.json` and `replace-reader.json` record those independent reads. The public test copies only the new native journal and checks an ordinary sync replaces text, arguments, status and result without duplicates. The procedure neither starts the CLI nor calls a model, auth service, network, or private history.

`ProviderRoots::from_home` uses `<home>/.vibe/logs/session/unified` and ignores host overrides. An environment-based root honors `VIBE_HOME` then `VIBE_SESSION_LOGGING__SAVE_DIR`, the latter taking precedence for the save directory. Explicit provider roots can represent a configured save directory. Project/user TOML configuration discovery is not implemented, so an operator whose Vibe process changes `session_logging.save_dir` in configuration must pass that root explicitly. Relative environment overrides are rejected because their meaning depends on Vibe's launch working directory, which a later RelayHistory process cannot recover; pass the resolved absolute provider root explicitly. Absolute and `~/` overrides are frozen when `ProviderRoots` is created and are not re-resolved during scans.

Public projection `message` entries preserve native entry IDs, recorded millisecond timestamps, roles and text blocks. A tool `effect` has a stable `effect-<actionId>` identity through running and settled updates, providing an exact call/result join; only explicit settled status supplies an error flag. Other public entries are bounded markers. Runtime `active_model`, context totals and checkpoint content do not prove per-message model or billable usage; those fields remain unknown. No native resume, child relationship, or file-edit claim is made. Discovery is passive and bounded to `CURRENT` plus metadata stamps, while selected hydration reads and validates the full native generation.

The native writer's `delete` removes the whole per-session directory. A missing `CURRENT` with an extant generation directory is treated as an incomplete or damaged store, so a full sweep retains the last good evidence. A complete clean sweep retires local evidence only after the whole session directory disappears. The same-millisecond reorder fixture is written as a fresh native generation and checks stable event IDs, event order, and unchanged tool status.

The public export contains the native event IDs and evidence, and remote intake preserves their content. Shared intake currently lacks a durable per-timestamp ordinal, so a later local hydration of remote-first evidence may return `FILE_HISTORY_SHARED_ORDER_CONFLICT` while retaining the accepted remote snapshot. [Issue #532](https://github.com/AgentWorkforce/relayhistory/issues/532) tracks the shared ordering and ownership contract; this adapter does not claim remote-first order parity until that contract is implemented.
