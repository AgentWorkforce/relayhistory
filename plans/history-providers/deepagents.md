# DeepAgents Code historical acquisition (#443)

Pinned source: `langchain-ai/deepagents` commit `0324ff31d18171fceddbd3084ff388b7a964c51b`, `deepagents-code` 0.1.88, macOS arm64. This is the `dcode` variant. It uses LangGraph's `AsyncSqliteSaver` for `sessions.db`; the bundled `deepagents-thread-inspector` is the independent read oracle. See [sessions.py](https://github.com/langchain-ai/deepagents/blob/0324ff31d18171fceddbd3084ff388b7a964c51b/libs/code/deepagents_code/sessions.py) and [inspect_sessions.py](https://github.com/langchain-ai/deepagents/blob/0324ff31d18171fceddbd3084ff388b7a964c51b/libs/code/deepagents_code/built_in_skills/deepagents-thread-inspector/scripts/inspect_sessions.py).

The writer stores `DEFAULT_STATE_DIR/sessions.db`; `_paths.py` resolves `DEEPAGENTS_HOME` (default `~/.deepagents`) and `DEFAULT_STATE_DIR` is its `.state` directory. In this pinned revision `DEEPAGENTS_SESSIONS_DB` is honored by the inspector only, not by `sessions.py::get_db_path()`. RelayHistory may use it as an explicit import override, but it cannot call it a native writer location. `history.jsonl` is the prompt-input recall file, not the transcript.

The SQLite schema has `checkpoints` and `writes`. The latest root (`checkpoint_ns=''`) checkpoint has serializer `type='msgpack'`; the fixtures prove checkpoint map versions `v=2` (materialized saver) and `v=4` (current compiled graph). `channel_values.messages` is an optional materialized message list. The current DeepAgents SDK can omit that list between `DeltaChannel` snapshots. To reconstruct the visible state, the official inspector starts at the latest inline list when present, otherwise starts empty, then folds ordered root `messages` writes. When inline exists it includes writes on the latest checkpoint; otherwise it folds all writes by `(checkpoint_id, task_id, idx)`. `Overwrite` resets the list, and LangGraph's `add_messages` deduplicates by native message ID and honors removal markers. Any importer must avoid multiplying the same message across checkpoint revisions. Child checkpoint namespaces do not belong to the root transcript.

Typed MsgPack message objects are Ext code 5 with a nested MsgPack `[module, class, kwargs, method]` tuple. The captured classes are allowlisted LangChain `HumanMessage`, `AIMessage`, and `ToolMessage` (`model_validate_json`); their kwargs preserve native ID, role, text content, tool calls and tool result IDs. The initial projection keeps decoded text; reasoning and other non-text content blocks are outside the claimed coverage. A Rust importer must decode data only, never execute object constructors or Python. Unknown extensions/classes are unsupported evidence, not successful empty history.

The fixture `crates/ai-hist/tests/fixtures/deepagents` was generated by the native `AsyncSqliteSaver` 3.1.2 and decoded in a separate Python interpreter by the official inspector. It proves two repeated checkpoints, a pending write, a resumed turn, and a tool call/result with ID `call-1`. A no-inline thread independently proves same-ID revision and removal, and a second no-inline thread proves `Overwrite` compaction does not resurrect prior text. The actual SDK DeltaChannel graph ran 57 deterministic invocations, crossed two 50-step inline snapshot boundaries, then revised and removed native IDs. Its `aget_state` 111-message result exactly matches the bundled inspector and the Rust adapter. The first oracle reports six messages in two user turns after restart. No model or network was invoked.

Tool arguments and tool-use event JSON are retained inline through 64 KiB. Larger native values are represented by bounded JSON containing the native call ID and name, encoded byte length, and SHA-256 of the full encoded value. This keeps default evidence export usable without implying that an oversized argument body was fully exported.
Decoded message text is kept inline through 32 KiB; larger text keeps a UTF-8 prefix plus the full native byte count and SHA-256. The prefix remains searchable, while content beyond it requires the native checkpoint. This bound applies to prompts, events, tool results, and the catalog's assistant summary so any of those rows can be exported within the default page budget.

Only the pinned current schema and root namespace are in scope for initial history coverage. Legacy `deepagents-cli` and alternate products, child subgraph namespaces, offloaded history, usage, file edits, and native resume remain unclaimed until native fixtures prove them. `session` metadata timestamps are reported as provider timestamp provenance; individual message timestamps are absent in this capture and must not be invented as provider timestamps.

Current DeltaChannel thread metadata has no `updated_at`; discovery reads the latest checkpoint's bounded MsgPack `ts` after a SQL size preflight. Invalid native timestamps leave prior good evidence and report the thread unread rather than substituting a filesystem mtime. Native UUIDv7 thread creation time anchors undated event rows, so distinct same-text user messages can share a timestamp. Their native IDs remain separate in conversation, event search, and exported session events; the shared `history` uniqueness key collapses identical text at that same timestamp. [#539](https://github.com/AgentWorkforce/relayhistory/issues/539) tracks a durable shared prompt identity without inventing message times.

Remote-first intake followed by local acquisition preserves imported evidence, but native order convergence can hit [#532](https://github.com/AgentWorkforce/relayhistory/issues/532) when events share a timestamp. The shared intake layer also has a [#535](https://github.com/AgentWorkforce/relayhistory/issues/535) local-first ownership limit; this provider does not claim arrival-order-independent remote/local parity.
