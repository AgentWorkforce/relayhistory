# Kilo Code CLI history acquisition

Issue: [#452](https://github.com/AgentWorkforce/relayhistory/issues/452). Current native variant: `@kilocode/cli@7.8.15` on macOS arm64, captured 2026-10-22. The official CLI uses `$XDG_DATA_HOME/kilo/kilo.db` (default `~/.local/share/kilo/kilo.db`) and supports `KILO_DB`; `:memory:` has no passive history. This provider observes only that local SQLite file and never runs Kilo, connects to cloud sessions, or resumes an agent.

Proof: synthetic inputs under `crates/ai-hist/tests/fixtures/kilo/` were written by the pinned CLI's `kilo import` in separate processes. Fresh `kilo export` calls after each writer exit independently returned the original message, part, and call IDs and decoded text. The captured SQLite schema has `session`, `message`, and `part` tables; message/part `data` are JSON, while the native IDs and millisecond timestamps are table columns. The capture README records exact provenance and limits. Legacy editor storage is unproven and excluded.

Normalization: native session IDs are scoped to the frozen database root; text and completed tool parts keep native message/part/call identities. One coherent read-only SQLite transaction captures each selected session or full sweep, including WAL-only commits. The payload stamp includes metadata and every message/part JSON body. Unsupported table layout fails with a diagnostic; malformed sibling bodies cannot retire good evidence. SQLite rows are bounded before materialization, and an absent primary database with a remaining WAL or journal does not prove deletion. Session token totals do not establish per-request billing, so usage remains unavailable. Parent IDs and non-text/non-tool parts are bounded metadata markers, not claimed relationships or edits. Remote same-timestamp order remains tracked by [#532](https://github.com/AgentWorkforce/relayhistory/issues/532). Local-first import of byte-identical remote evidence cannot take ownership of direct-parser rows before their deletion under the shared intake contract; [#535](https://github.com/AgentWorkforce/relayhistory/issues/535) tracks that independent limitation. Remote-first intake followed by local sync and retirement is covered here.

Tool arguments above 256 KiB become a bounded JSON projection with the native payload byte count and SHA-256 hash; the native call ID and tool name remain intact. Oversized tool results preserve a decoded searchable prefix with a bounded projection. A native pending/running rewrite clears a prior local error status and completed result.

Probes still outside this format: authenticated remote sessions, native resume, older VS Code extension records, model-generated usage, and broader content variants. These remain unavailable until independently captured.
