## Frozen roots and native identities

`GEMINI_CLI_HOME`, when non-empty, replaces the home base; otherwise upstream uses `os.homedir()`. The normal runtime tree is `<base>/.gemini`. With exactly `SANDBOX=sandbox-exec`, runtime data moves to `<base>/.cache/.gemini`; the home override applies before this switch. Other sandbox values do not themselves change this resolver, though a container may mount ephemeral runtime storage. The checked-in `root-oracle.json` executes these actual functions with five injected environment cases, without modifying process environment or reading a user's configuration.

Current `Storage.initialize()` obtains a project slug from `<runtime>/projects.json`, whose map is normalized absolute project path to slug. Ownership markers are `<runtime>/tmp/<slug>/.project_root` (also under history), and older SHA256 project directories migrate to the slug. The recorder therefore writes `<runtime>/tmp/<project-identifier>/chats/`; discover both slug and legacy hash directories rather than assuming a 64-character hash. `projectHash` inside session metadata still hashes the project root and is not the current directory name. Registry/ownership marker resolution is source-inspected, not exercised by the fixture harness, which injects a known slug. The passive adapter never calls initialization or migration to discover files.

Main filenames are `session-<minute timestamp>-<first-eight-session-characters>.jsonl`, optionally with a collision index. The full `sessionId` comes from file metadata, not the short suffix. The actual writer fixture proves a filename-prefix collision creates two distinct full UUID sessions. Message identity is the stored `id`; append revisions reuse it. Main IDs in these fixtures are UUIDs, but the writer accepts the context's non-empty sanitized ID, so implementation must not infer that every child ID is necessarily UUID-shaped.

Subagent files are `<chats>/<sanitized complete parent id>/<sanitized child id>.jsonl`; metadata contains the child's full `sessionId`, `kind: subagent` and workspace directories, without a `parentSessionId` field. The folder is relationship evidence only when it can be joined to a parent's verified full ID using the upstream sanitizer. Do not invent tool/delegation joins from a basename or similarity. Distinct explicitly configured home roots need collision-safe namespaces, using frozen resolver provenance rather than repeated environment reads.

## Journal and legacy semantics

The current file is an append-only mutation journal, not a line-per-message transcript:

| Record | Official logical projection |
| --- | --- |
| Initial metadata | `sessionId`, `projectHash`, times, kind and optional directories. |
| Message with `id` | Insert or replace that ID while preserving its existing insertion position. |
| `$set` | Merge metadata; deprecated `messages` checkpoints replace the full logical message set. |
| `$patch.id` / `$patch.updates` | Replace message content and update existing tool results by actual call ID. |
| `$patch.removeIds` | Remove named logical messages. |
| `$patch.orderIds` | Reorder referenced existing IDs after the unreferenced prefix. |
| `$rewindTo` | Remove the target ID and all following logical messages; unknown target clears the set. |

Resume reloads the file, preserves the full native ID/start time and appends metadata and new turns. The recorder's 50-message in-memory window does not mean only 50 messages persist; the official reader reconstructs full history unless given bounded options. The production parser replays admitted mutations coherently, deduplicates repeated IDs, and handles later patches against earlier messages. Fingerprints must cover exact bytes and filename/rotation changes; incomplete final lines should be deferred without sealing a complete generation.

Legacy `.json` contains one `ConversationRecord`. The current reader accepts it, and resume migrates it to a sibling `.jsonl`, retaining the `.json` file and full UUID. The fixtures prove this current migration path using a synthetic legacy object. An old real writer version remains unpinned; do not describe the JSON fixture as captured by that historical writer. The production adapter deduplicates retained JSON/JSONL revisions using metadata identity and coherent logical precedence.

Compression has two relevant paths. Full chat compression creates synthetic summary user/model turns and restarts the chat with the existing recording data; `GeminiChat` reconciles the new history through recorder patches. Tool-output compression alters function responses, which updates the original tool result by its call ID. The fixture exercises both forms through the actual persistence API with synthetic histories and results; it performs no summarizing model call. Removed/rewound turns remain physically present in the journal while the official logical view drops them.

There is no dedicated persisted compaction opcode or per-message synthetic flag: `recordSyntheticMessage` uses the regular message shape. A summary may be a `user` record, and ordinary user text can resemble summary markup. Production design must distinguish finalized logical messages from superseded journal evidence without presenting synthetic summaries/tool responses as human requests or treating every `removeIds` as proven compaction. The implemented projection below preserves archived raw mutation evidence as markers while normalizing finalized messages, without guessing user intent.

## Evidence available and limits

- User and `gemini` assistant text are available as strings or content-part arrays; preserve text/thought/tool blocks and do not flatten function responses into human prompts. `info`, `error` and `warning` records are status evidence, not human turns.
- `thoughts` contain subject/description/timestamp summaries, not necessarily raw reasoning. Preserve the recorded summary and its provenance.
- Tool records carry their real ID, name, args, timestamp, status and optional result; results may be part arrays, strings or null. Current patches update results without replacing the call identity. Status requires explicit mapping to existing result states; the fixture proves `executing`→`success`, while remaining status spellings need scheduler-source verification before admission. No file edits are inferred from a tool's name/path.
- GeminiChat records the last usage metadata from the successful response attempt, once into the assistant message. The writer maps prompt/output/cache/thought/tool/total counts and defaults missing individual fields to zero when usage metadata exists. A missing/null `tokens` object stays unavailable. These are recorded response measurements, not a complete account of failed retries or independent compression requests; do not promise complete billing. Cached counts may be a subset of input and must not be double-added. No request ID or pricing is invented.
- Times are ISO strings generated at recording/metadata update; model is stored per assistant message. Project hash is not cwd. Main cwd recovery needs verified registry/ownership metadata; child `directories` are explicit workspaces, not necessarily execution cwd.
- Files have no schema-version field. Unsupported opcodes, bad identities/types and complete corruption need diagnostics. Upstream skips malformed JSONL lines; using that reader's successful result alone cannot prove complete acquisition. The research validator deliberately rejects complete malformed records and defers an incomplete final record.
- Passive roots/tree acquisition appears feasible. No authenticated export is required for the tested files. Native CLI resume is documented but not executed, and no resume or live capability is admitted here.

## Production acquisition decisions (2026-10-14)

The admitted roots are the recorder's runtime `tmp` directory, resolved once: native `<home>/.gemini/tmp`, seatbelt `<home>/.cache/.gemini/tmp`, with non-empty `GEMINI_CLI_HOME` replacing the home base before the seatbelt rule. Discovery accepts both slug and hash project directories and full child paths under `chats`; it never invokes registry migration. The runtime project registry and `.project_root` markers are not read, so cwd and project key remain unavailable instead of treating a project hash as a path. Child directories and metadata remain raw evidence, with no inferred parent relationship.

Native-root ledger session IDs are full recorded session IDs. Explicit custom roots add a SHA256 root namespace, with the native ID also retained in metadata. Prefix filenames never establish session identity. Duplicate live native IDs are rejected except a verified same-stem legacy migration pair. JSONL takes precedence in enumeration; a retained catalog JSON locator also captures and validates its journal sibling. Acquisition stamps exact bytes and both read paths for that alias. Legacy JSON is the synthetic current-reader input described above, not evidence from a pinned old writer. The bounded metadata prefix requirement is tested explicitly and is an unsupported serialization ordering, not silent empty success. Bounded shallow reads accept its metadata-before-`messages` serialization; reordered objects whose identity lies after `messages` return a diagnostic rather than reading an unbounded array.

Journal projection follows the independently captured official reader for all nine cases. A HashMap plus ordered IDs avoids quadratic ordinary append/replacement. `$set` checkpoints, repeated IDs, `$patch` content/tool results/removal/order, and `$rewindTo` all settle before normalization. Every physical record is retained as a bounded raw `journal_record` marker, including superseded messages. Public message pages keep the SDK's timestamp ordering; the exact logical `orderIds` evidence is retained in markers and tested against the official reader projection. Malformed complete records and unsupported opcodes/patch fields fail without overwriting prior evidence. An incomplete EOF fragment is deferred, stamped, diagnosed and prevents a complete sweep fingerprint.

Finalized messages retain the recorded `user`/`gemini` roles. Function responses, status notifications and thought summaries are markers, not human prompts. The writer has no reliable discriminator between a real user message and `recordSyntheticMessage`: finalized summary-shaped user text therefore retains its recorded role, including when a destructive reorder touched it. **Human-versus-synthetic classification and an authoritative compaction boundary are unavailable.** No heuristic based on markup, `removeIds`, filenames, or content similarity is used. Retained raw mutations expose the distinction consumers can actually verify. Archived/superseded records remain markers, not additional active prompt rows.

Tools join only by recorded call IDs; patched assistant call results are authoritative. Captured `success` maps to completed, while other spellings retain raw status without an invented outcome. Tool names and args never imply file edits. Thought summaries remain explicitly labeled summaries. Measured response tokens normalize per message; the native input count includes cached input, so normalization subtracts cached reads with checked arithmetic and exposes cache-exclusive input plus a separate cache-read count. Overlarge cache counts are errors; missing native input keeps input coverage unavailable. The provider's `tool` count remains in raw usage; missing counts retain coverage flags and missing token objects remain unavailable. No pricing, retry completeness, model compression requests, resume or live execution is claimed.

Rewrites use the shared evidence retirement helper, so removing a local share preserves a remote share. Scoped sweeps preserve unvisited cursors; parser generation changes and the standard repair set trigger replay. Local snapshot acquisition is passive and makes no auth, model, remote network or provider CLI calls. Images/URLs/paths in content are opaque recorded parts and are never dereferenced.

The checked-in `surface-proof.mjs` stages only the synthetic ordinary session and proves SDK discover/hydrate/search/source filtering/capabilities, CLI search, and MCP search/capabilities. It explicitly clears Gemini root and sandbox environment overrides. The shared SDK test environment scrubber now includes those variables, and its unknown-source regression uses a genuinely unregistered source. The integration owner supplied the changelog entry; generated public API adds only `Source::Gemini`.
