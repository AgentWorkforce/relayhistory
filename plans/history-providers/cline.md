# Cline core v1 history acquisition

Issue #438. Pinned `cline/cline` `c441897f11f658f978a00678f045670c1ab2b60d`, current SDK/CLI session artifact on macOS arm64. The native writer's `buildMessagesFilePayload` persists version-1 `<sessionId>.messages.json` under `resolveSessionDataDir`; `SessionManifestStore.persistSessionMessages` writes a populated JSON snapshot. The independent `readPersistedMessagesFile` runs after process restart, and the CLI `history export` route reads through `core.readMessages`. Exact executed synthetic proof and hashes are in [fixture README](fixtures/cline/README.md). This does not cover legacy VS Code task storage.

The root precedence is `CLINE_SESSION_DATA_DIR`, `CLINE_DATA_DIR/sessions`, `CLINE_DIR/data/sessions`, default `<home>/.cline/data/sessions`, with explicit RelayHistory `ProviderRoots` taking precedence for its scan. The adapter enumerates only one directory level and the exact `<id>.messages.json` child. It never invokes Cline or an account/model endpoint. It validates root containment, native version/identity, block shape and stable IDs, then transactionally normalizes whole snapshots. Discovery also parses the snapshot to obtain native first-prompt and timestamp metadata; both discovery and hydration stop after a fixed 32 MiB + 1 byte read and diagnose oversized artifacts. Complete rewrites retire removed records. Invalid concurrent partial writes, unreadable paths and malformed siblings leave last-good evidence and report a diagnostic. Deletion requires an accessible authoritative sweep and confirmed file absence.

Stable native message IDs become event IDs with content-block ordinals. Text and thinking are searchable/readable; tool IDs join use and result blocks. A user envelope with both text and a tool result contributes only its text blocks to prompt history. Oversized user prompts, assistant text, and thinking become bounded visible-prefix projections with native text byte count and hash; search covers the retained prefix, and the marker explicitly records truncation. Each retained user prompt also has a bounded support marker keyed by native message ID and timestamp and containing the full SHA256 of its projected text. The marker retires with the message; matching surviving marker evidence keeps a shared projected prompt when its former owner disappears, while deletion of all support removes the prompt. A mixed tool result retains decoded visible text and an exact native-content projection when it fits export limits; oversized content has a bounded, explicitly truncated projection with native payload byte count and hash. Oversized tool-use event text and call arguments likewise become bounded projections retaining tool ID/name and the native input's byte count/hash; small inputs remain exact. Unknown blocks and terminal metrics remain bounded markers. User timestamps are derived and marked, because the writer only promises assistant `ts`. `modelInfo` is attached only when present. Cline's metrics may be per-turn or fallback run totals, so normalized usage remains unavailable. No inferred file edits, parent-child relationships, or executable resume command are advertised. The provider uses the same public facade, change feed and export as other local sources. Remote same-timestamp event order remains limited by #532; local-first import ownership remains limited by #535. The remote-first/local-deletion regression does not claim arrival-order parity.
