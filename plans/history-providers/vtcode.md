# VT Code historical acquisition (#460)

Pinned producer: VT Code 0.180.2, public release of 2026-10-20, source tag target `a568dbb4b662617dad2b4914a2455cb34c474673`, macOS/Unix workspace layout. The `vtcode-memory` 0.180.2 `SessionEventLog::append` writer serializes `vtcode-exec-events` `VersionedThreadEvent` at schema 0.18.0 into `<workspace>/.vtcode/sessions/<session_id>/events.jsonl`. `visit_snapshot` is the separate native reader API. The manifest and turn index are derived and do not replace the journal. [Writer](https://github.com/vinhnx/VTCode/blob/0.180.2/crates/codegen/vtcode-memory/src/event_log.rs) · [event schema](https://github.com/vinhnx/VTCode/blob/0.180.2/crates/common/vtcode-exec-events/src/lib.rs) · [configuration](https://github.com/vinhnx/VTCode/blob/0.180.2/docs/config/config.md).

The official `agent.harness.event_log_path` is an optional compatibility/export sink. The Open Responses `derived/open-responses.jsonl` is also derived. Acquisition uses only canonical journals, so an enabled export cannot duplicate a session. Native `continue`/trajectory commands establish no RelayHistory resume promise; this provider leaves resume unavailable.

Discovery is limited to the workspace containing `ProviderRoots.home` for `from_home`, plus explicitly listed `RELAYHISTORY_VTCODE_WORKSPACES` for `from_env`. That variable belongs to RelayHistory, not VT Code. Each path is frozen, absolute, normalized and deduplicated; no home-wide workspace hunt or model/network/auth access occurs. Workspaces outside this declaration are absent from discovery by design. A native session ID repeated in two workspaces receives distinct ledger identity while the original ID remains in raw evidence. An absent declared workspace is an empty candidate set, while malformed/denied/unsupported evidence is diagnostic.

The persisted `turn.started.context.goal` is a human prompt only when `context.origin=user`; continuation/retry retains a task goal and is a control event. Assistant text is `item.completed` with `item.type=agent_message`; item IDs are native. Tool invocation/output join by `tool_call_id`/`call_id`; no file edits or child relationship is inferred from mere tool output. `turn.completed.usage` is the per-turn usage evidence; `thread.completed.usage` is an aggregate and must not be counted again. There is no evidenced model identity in this event family. Timestamps on turn and items come from their `context.timestamp`; terminal-only records have their own completion timestamp.

Fixture capture is authored synthetic event input passed through the released VT Code writer, followed by a separate process reopening the released store and decoding through `visit_snapshot`. The input itself is not represented as an observed private VT Code run. The fixture README records exact commands, native reader projection, and limitations.
